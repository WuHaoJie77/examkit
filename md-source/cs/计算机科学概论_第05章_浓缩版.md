## 一、语言层次：从自然语言到机器语言

> 🍳 **费曼：自然语言像「日常聊天」——同一句话"我去银行"可能是存钱也可能是去河边（歧义）。形式语言像「合同条款」——每个词精确定义，不会有第二种解释。机器语言像「摩斯密码」——只有0和1，人看得头疼但机器秒懂。高级语言像「普通话」——接近人话，翻译官（编译器）帮你翻成摩斯密码。**

### 1.1 自然语言 vs 形式语言

| | 自然语言 | 形式语言 |
|------|----------|----------|
| 本质 | 民族语言（汉语、英语） | 以数学和**数理逻辑**为基础的科学语言 |
| 特征 | **歧义性**、语法松散 | 专门符号集、精确定义规则、**无歧义** |
| 用途 | 人际交流 | 程序设计、逻辑推理 |
| 可直接编程？ | ❌ | ✅ |
| 计算机处理分类 | **文字和语音** | — |
| 科学语言特性 | 描述性、**断定性**（非评论性） | — |
| 输入方式 | 键盘、语音、手写 | — |

### 1.2 机器语言 vs 汇编语言

| | 机器语言 | 汇编语言 |
|------|----------|----------|
| 符号集 | **{0,1}** 二进制 | 助记符（MOV、ADD）+ 字符/数字 |
| 可读性 | 极差 | 有所提升 |
| 可执行性 | **硬件直接执行** | 需汇编程序翻译 |
| 移植性 | 差（依赖硬件） | 差（仍依赖硬件） |
| 理论基础 | 图灵机等计算模型 | — |
| 与指令对应 | — | 与机器指令**一一对应** |

> ⚠️ **支撑机器语言的理论基础是图灵机，不是冯·诺依曼模型！冯·诺依曼模型是硬件结构模型。**
> ⚠️ **形式化语言是人工语言符号系统发展的第**二**阶段，不是第三阶段。**

### 1.3 语言层次关系

```
自然语言（交流用）→ 形式语言（科学基础）
                              ↓
机器语言（{0,1}，硬件直接执行）
    ↓ 汇编程序翻译
汇编语言（助记符，一对一）
    ↓ 编译/解释
高级语言（接近自然语言和算法语言）
```

## 二、高级语言与程序设计范型

> 🍳 **费曼：四种编程范型就像四种写作风格——命令式像「操作指南」(先做A再做B)，面向对象像「人物传记」(每个人都有属性和行为)，函数式像「数学公式」(输入→输出，无副作用)，逻辑型像「侦探推理」(给定事实和规则，让系统自己推导结论)。**

### 2.1 高级语言四大特点

| 特点 | 说明 |
|------|------|
| ① **易学易掌握** | 接近自然语言和算法语言，短期培训可用 |
| ② **结构化设计** | 可读性、可维护性、可靠性高（结构化程序核心强调**易读性**！） |
| ③ **可移植性好** | 与硬件关联小，跨平台重用 |
| ④ **自动化程度高** | 编译程序处理细节，开发周期短 |

### 2.2 四大程序设计范型

| 范型 | 核心思想 | 代表语言 | 关注点 |
|------|----------|----------|--------|
| **命令式(过程型)** | 基于动作序列 | Fortran、C、Python | 「如何做」 |
| **面向对象** | 对象、类、继承、多态 | C++、Java、Python | 「谁来做」 |
| **函数式** | 基于函数映射、递归 | LISP、Haskell | 「是什么」 |
| **逻辑型** | 基于**形式逻辑** | **Prolog** | 「条件→结论」 |

> 🐍 **Python = 命令式 + 面向对象 + 解释型 + 动态类型 + 脚本语言**

## 三、程序设计语言构成元素

> 🍳 **费曼：语言元素像「造房子的材料」——字符集是砖的种类，标识符是房间门牌号，关键字是承重墙(不能动)，操作符是工具，界定符是墙的分界线，表达式是功能间(厨房/客厅)，语句是施工步骤，注释是施工便条(工人不看)。**

### 3.1 八大构成元素

| 元素 | 定义 | 例子 |
|------|------|------|
| **字符集** | 语言设计**第一件事** | ASCII字符集 |
| **标识符** | 命名变量/函数/类的符号串 | `user_name`（字母/数字/下划线） |
| **关键字（保留字）** | 预定义符号，不可重命名 | `if`、`class`、`while` |
| **操作符** | 表示运算的符号 | 算术(`+`)、逻辑(`&&`)、比较(`>`)、赋值(`=`) |
| **界定符** | 标记语法边界 | `{}`、`()`、`;` |
| **表达式** | **操作数+操作符**组成的有意义式子 | `a + b * c` |
| **语句** | 程序执行单元 | 赋值语句、循环语句 |
| **注释** | 不参与编译的说明 | `// 这是注释` |

### 3.2 匈牙利命名法

```
标识符 = 属性 + 类型 + 对象描述

例：frmSwitchboard → 属性(frm=表单) + 对象描述(Switchboard)
    lblTitle      → 属性(lbl=标签) + 对象描述(Title)
```

> 适用：多人协作大型项目，增强代码可读性

## 四、数据成分与控制成分

### 4.1 数据成分

| 概念 | 定义 |
|------|------|
| **常量** | 程序运行中**值不变**的数据 |
| **变量** | 程序运行中**值可改变**的数据 |
| **全局量** | 全程序可访问，启动创建，长期占用空间 |
| **局部量** | 仅函数/模块内可访问，执行完释放 |
| **静态变量** | 程序运行期间存在，仅在说明它的函数内可见 |

### 4.2 控制成分（三大结构）

| 结构 | 说明 |
|------|------|
| **顺序结构** | 逐条执行 |
| **选择结构** | 条件分支（if-else） |
| **循环(重复)结构** | while / do-while / for |

### 4.3 while vs do-while

| | while型 | do-while型 |
|------|---------|------------|
| 判断时机 | **先判断**再执行 | **先执行一次**再判断 |
| 最少执行次数 | 0次 | **至少1次** |
| 适用 | 次数不确定，需先验证条件 | 必须至少执行一次 |

### 4.4 函数 vs 过程（子程序）

| | 函数 | 过程 |
|------|------|------|
| 返回值 | **有返回值** | 无返回值 |
| 调用方式 | 作为**表达式** | 作为**语句** |

> 🔑 **子程序**：可被调用、执行功能后自动返回的程序（函数+过程的统称）
> 🔑 **C语言中函数的数据类型 = 返回值的数据类型**

## 五、编译 vs 解释 vs 混合

> 🍳 **费曼：编译像「整本书翻译」——翻译官把整本英文书译成中文，你拿中文版随便看（快但改了原文得重译）。解释像「同声传译」——说一句翻一句，不用等全书译完（灵活但慢）。混合像「先译成世界语再逐句口译」——折中方案（Java→字节码→JVM解释）。**

### 5.1 三种途径对比

| | 编译 | 解释 | 混合（编译+解释） |
|------|------|------|------|
| 过程 | 一次性全部翻译 | 逐行翻译执行 | 先编译为中间代码→再解释执行 |
| 生成目标程序？ | ✅ 生成 | ❌ 不生成 | 生成中间代码 |
| 执行效率 | **高** | 低 | 中 |
| 修改后 | 需重新编译 | 直接执行 | 需重新编译为中间代码 |
| 可移植性 | 差（目标代码平台绑定） | 好（有解释器就行） | **好**（中间代码跨平台） |
| 代表 | C、C++ | Python、JavaScript | **Java**（字节码+JVM）、.NET |

### 5.2 编译程序五阶段

```
源程序 → ①词法分析 → ②语法分析 → ③中间代码生成 → ④代码优化 → ⑤目标代码生成
```

| 阶段 | 做什么 |
|------|--------|
| 词法分析 | 拆分为单词符号 |
| 语法分析 | 检查语法结构，生成语法单位 |
| 中间代码生成 | 生成中间语言（如四元式） |
| 代码优化 | 提升效率 |
| 目标代码生成 | 转为机器语言 |

> ⏱️ **编译程序绝大多数时间花在「表格管理」（符号表/常数表管理）**

### 5.3 伪编译

将源程序转为接近机器语言的**中间代码**，需运行环境支持执行。

### 5.4 构造编译程序需掌握

源程序 + 目标语言 + 编译方法（三者缺一不可）

## 六、IDE与DLL

### 6.1 IDE（集成开发环境）

| 核心工具 | 功能 |
|----------|------|
| **源代码编辑器** | 语法高亮、代码提示、格式规范 |
| **编译器/解释器** | 自动调用，生成目标程序 |
| **调试器** | 断点、单步跟踪、查看变量值 |
| **项目管理器** | 管理源文件、资源文件、版本控制 |

> 代表：PyCharm (Python)、Visual Studio (多语言)

### 6.2 DLL（动态链接库）

| 优点 | 说明 |
|------|------|
| **程序模块化** | 功能拆分为独立DLL |
| **方便升级** | 只更新DLL文件，不重装整个程序 |
| **加载速度快** | 按需动态加载 |

> ⚠️ DLL本身是编译产物，「程序不用编译」不是DLL的优点！

## 七、Python专题

### 7.1 Python语言定位

| 维度 | 分类 |
|------|------|
| 范型 | 命令式 + 面向对象（也支持函数式） |
| 执行方式 | **解释型**（也可以伪编译为字节码） |
| 类型系统 | 动态类型 |
| 层次 | 高级程序设计语言 |
| 用途 | 脚本语言 |

### 7.2 Python流行的原因

1. 语法简洁易学（接近自然语言，代码量少）
2. 多范型支持（命令式+面向对象+函数式）
3. 丰富库生态（NumPy/Pandas/Django）
4. 跨平台性（Windows/macOS/Linux）
5. 应用场景广泛（数据分析/AI/Web/自动化）
6. 解释型优势（改完直接跑，调试方便）
7. 社区活跃（资源多，学习门槛低）

### 大题参考答案

**16. 自然语言 vs 形式语言**

| | 自然语言 | 形式语言 |
|------|----------|----------|
| 概念 | 民族语言（汉语、英语） | 以数学+数理逻辑为基础的科学语言 |
| 特征 | 歧义性、语法松散 | 专门符号集、精确定义、无歧义 |
| 用途 | 人际交流 | 程序设计、逻辑推理 |

自然语言不能直接编程的原因：有歧义（同一句话多种解读）、语法不严格（机器无法精确解析），必须用无歧义的形式语言。

**17. 编译 vs 解释 vs 混合**

| | 编译 | 解释 | 混合 |
|------|------|------|------|
| 生成目标程序？ | ✅ 是 | ❌ 否 | 生成中间代码 |
| 效率 | 高 | 低 | 中 |
| 可移植性 | 差 | 好 | **好**（跨平台） |
| 代表 | C/C++ | Python/JS | **Java**(字节码+JVM) |

Java采用混合方式：先编译为字节码（中间代码）→JVM解释执行。兼顾效率（字节码接近机器码）+跨平台（同一份字节码各平台JVM都能跑）。

**18. 编译五阶段**

源程序 → ①**词法分析**（拆单词）→ ②**语法分析**（检查结构）→ ③**中间代码生成** → ④**代码优化** → ⑤**目标代码生成**

设计需考虑：语法全覆盖、错误处理（准确提示）、代码优化、目标平台适配、兼容性、编译速度。

**19. 八大构成元素**

| 元素 | 作用 |
|------|------|
| 字符集 | 语言可使用的全部符号（设计第一件事） |
| 标识符 | 命名变量/函数/类 |
| 关键字 | 预定义符号，不可重命名 |
| 操作符 | 算术/逻辑/比较/赋值运算 |
| 界定符 | 标记语法边界 `{}()` |
| 表达式 | 操作数+操作符=有意义式子 |
| 语句 | 程序执行单元 |
| 注释 | 不参与编译的说明 |

**20. 四组对比**

| while vs do-while | while先判断→可能0次 | do-while先执行→至少1次 |
|------|------|------|
| 函数 vs 过程 | 函数有返回值(表达式调用) | 过程无返回值(语句调用) |
| 匈牙利命名法 | 标识符=**属性+类型+对象描述** | 例：frmSwitchboard |
| 子程序 | 函数+过程的统称，可被调用执行后返回 | |

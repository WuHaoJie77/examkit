## 一、操作系统概述

> 🍳 **费曼：操作系统像「酒店前台+管家」——你(用户)不需要知道房间怎么打扫、水电怎么走，只要跟前台说要入住(用户接口)，管家会调度房间(进程管理)、管理行李(存储管理)、登记资料(文件管理)、安排服务员(设备管理)。裸机就是没前台没管家的空楼，你什么都不会用。**

### 1.1 定义与定位

| 方面 | 内容 |
|------|------|
| **定义** | 管理计算机系统资源、控制程序执行、改善人机界面、提供各种服务的**系统软件** |
| **定位** | 用户与计算机硬件之间的**接口**，为应用程序提供运行环境 |
| **本质** | 计算机系统的**资源管理者** |
| **裸机** | 没有安装**任何软件**（含OS）的计算机 |

### 1.2 三大组成单位

| 单位 | 定义 | 特征 |
|------|------|------|
| **内核** | 管理硬件及资源，处理中断 | 中断驱动、连续执行、屏蔽中断、使用特权指令，现代多用**微内核** |
| **进程** | 程序关于某数据集合的一次执行过程 | 资源分配和保护的基本单位 |
| **线程** | 进程中的执行路径 | 系统调度的独立单位，降低并发开销 |

## 二、操作系统六大功能

> 🍳 **费曼：OS六大功能像「酒店的六个部门」——前台部(用户接口)、客房部(处理器管理)、仓管部(存储管理)、档案部(文件管理)、工程部(设备管理)、外联部(网络管理)。**

| 功能 | 核心任务 |
|------|----------|
| ① **处理器管理** | 处理中断事件、处理器调度，提高CPU利用率 |
| ② **存储管理** | 管理主存：分配、共享、地址转换、保护、扩充 |
| ③ **文件管理** | 管理外存文件：**存储、检索、更新、共享、保护**，按名存取 |
| ④ **设备管理** | 控制**外围设备与CPU**之间的I/O操作 |
| ⑤ **网络与通信管理** | 管理网上资源、数据通信、故障/安全/性能管理 |
| ⑥ **用户接口** | 程序接口+操作接口，方便用户调用系统功能 |

## 三、操作系统分类

> 🍳 **费曼：批处理像「团购网站」——凑满一单一起处理(吞吐量大，但你没反馈权)。分时系统像「银行柜台」——多个窗口轮流服务多个客户(交互性强)。实时系统像「心脏起搏器」——错过一秒就要命(及时+高可靠)。**

### 3.1 按运行模式

| 类型 | 核心特征 | 优点 | 代表 |
|------|----------|------|------|
| **批处理系统** | 成批处理、**脱机工作**、单CPU多道程序**轮流运行** | 吞吐量大、资源利用率高、系统开销小 | 早期大型机 |
| **分时系统** | 多用户联机、**同时性/独立性/及时性/交互性** | **响应及时**、交互性强 | UNIX |
| **实时系统** | **及时响应、高可靠性** | 毫秒级响应 | 自动驾驶、工业控制 |

> ⚠️ **批处理=脱机工作，交互性是分时系统的特征！批处理没有交互性！**
> ⚠️ **批处理系统优点不包括"响应及时"！响应及时是分时系统的优点。**
> ⚠️ **早期批处理解决的是手工操作的「脱机」问题，不是联机问题。**

### 3.2 按应用形态

| 类型 | 特征 | 例子 |
|------|------|------|
| **微机操作系统** | 单用户多任务 | **Windows** |
| **网络操作系统** | C/S或对等模式 | UNIX、Netware |
| **分布式操作系统** | 透明管理多台互联计算机 | — |
| **嵌入式操作系统** | 实时高效、资源受限 | VxWorks、嵌入式Linux |
| **移动操作系统** | 简洁、依赖无线通信 | iOS、Android |

> 🪟 **Windows = 单用户多任务，UNIX = 多用户多任务**

## 四、进程管理

> 🍳 **费曼：程序像「菜谱」(静态纸)，进程像「正在做菜」(动态过程)。同一份菜谱可以被多个厨师同时做(一个程序→多个进程)。每个厨师有自己的备菜区(数据块)+菜谱复印件(程序块)+进度记录卡(PCB)。**

### 4.1 进程 vs 程序

| | 程序 | 进程 |
|------|------|------|
| 性质 | **静态**指令序列 | **动态**执行过程 |
| 存在 | **永久**存在 | 有生命周期 |
| 关系 | 一个程序→多个进程 | 一个进程→一个程序 |

> ⚠️ **进程≠作业！作业是用户要求的独立工作，进程是作业的执行过程。**
> ⚠️ **进程在不同系统中有不同名称：任务(Task)、活动(Active)**

### 4.2 进程三要素

```
进程 = 程序块 + 数据块 + 进程控制块(PCB)
```

### 4.3 进程四大属性

| 属性 | 说明 |
|------|------|
| 结构性 | 由程序块+数据块+PCB组成 |
| 动态性 | 有生命周期（创建→就绪→执行→阻塞→终止） |
| 独立性 | 独立分配资源 |
| 并发性 | 多个进程可并发执行 |

### 4.4 进程状态转换

```
创建 → 就绪 → 执行 → 终止
         ↑      ↓
         ← 阻塞 ←
```

| 转换 | 触发条件 |
|------|----------|
| 就绪→执行 | 低级调度（进程调度） |
| 执行→阻塞 | I/O请求发起 |
| 阻塞→就绪 | **I/O请求完成** |
| 后备→执行 | 高级调度（**作业调度**） |

### 4.5 处理器三级调度

| 级别 | 别称 | 作用 |
|------|------|------|
| **高级调度** | **作业调度** | 后备队列→主存，创建进程（后备→执行） |
| **中级调度** | 平衡负载调度 | 挂起↔就绪 |
| **低级调度** | 进程/线程调度 | 就绪→执行 |

> 🔑 **现代OS用「进程调度+线程调度」结合完成多处理器调度**

### 4.6 进程控制操作

创建进程 → 阻塞进程 → 唤醒进程 → 挂起进程 → 激活进程 → 终止进程 → 撤销进程

## 五、死锁

> 🍳 **费曼：死锁像「两个人都过独木桥」——A走到中间不让，B也走到中间不让，谁也过不去，永远僵持。四个人条件全满足才死锁：桥只能一个人走(互斥)、A占着桥还想过B的桥(请求保持)、不让硬抢(不剥夺)、A等B、B等A形成圈(循环等待)。**

### 5.1 死锁四个必要条件

| 条件 | 说明 | 破坏方法 |
|------|------|----------|
| ① 互斥 | 资源只能被一个进程独占 | 难破坏（资源固有属性） |
| ② **请求与保持** | 持有部分资源又请求其他 | **一次性申请全部资源** |
| ③ 不剥夺 | 已占资源不可强制剥夺 | 允许剥夺（不现实） |
| ④ **循环等待** | 进程间形成资源请求循环链 | **按序号顺序申请资源** |

> 🔑 **四个条件相互独立，缺一不可。破坏任一条件即可防止死锁。**

### 5.2 死锁避免公式

```
安全条件：M ≥ N × (W-1) + 1

M = 系统总资源数
N = 进程数
W = 每个进程需要的资源数

满足→安全（不会死锁）  不满足→可能死锁
```

| 例 | M | N | W | 公式计算 | 结果 |
|----|---|---|---|--------|------|
| 1 | 2 | 2 | 1 | 2 ≥ 2×0+1=1 | ✅ 安全 |
| 2 | 3 | 2 | 2 | 3 ≥ 2×1+1=3 | ✅ 安全 |
| 3 | 3 | 2 | 3 | 3 ≥ 2×2+1=5 | ❌ 可能死锁 |

### 5.3 死锁解除方法

资源剥夺法 → 进程回退法 → 进程撤销法 → 系统重启法

## 六、存储管理

### 6.1 存储器六层层次

```
寄存器 → 高速缓存(Cache) → 主存储器 → 磁盘缓存 → 固定磁盘 → 可移动存储介质
  ↑                                                              ↓
最快/最贵/最小/CPU直接访问                                    最慢/最便宜/最大/间接访问
```

### 6.2 虚拟内存

| 方面 | 内容 |
|------|------|
| 定义 | 作业仅当前使用部分入主存，其余暂存外存，用时自动调入。逻辑地址空间可大于物理地址空间 |
| 设置大小 | 通常为物理内存的**1.5~2倍** |
| 注意 | 不是越大越好，过大会导致频繁交换降低效率 |

### 6.3 Cache命中率计算

```
平均访问时间 = T_cache + (1-H_cache) × [T_mem + (1-H_mem) × (T_disk + T_mem)]

其中 H = 命中率
```

## 七、文件系统

> 🍳 **费曼：顺序文件像「磁带」——只能从头到尾听，快进可以但慢。索引文件像「目录书」——翻目录(索引表)直接跳到你想要的页。散列文件像「哈希表」——用公式算出你的东西在哪个抽屉，最快但偶尔两个东西算出同一个抽屉(冲突)。**

### 7.1 逻辑结构

| 类型 | 说明 |
|------|------|
| **记录式文件** | 有结构，由记录组成 |
| **无结构文件(流式)** | 无结构，如纯文本 |

### 7.2 存取方式

| | 顺序存取 | 随机存取 |
|------|----------|----------|
| 方式 | 按排列顺序依次存取 | 直接定位，与排列无关 |
| 特点 | 简单实用 | 灵活高效 |
| 适合 | 连续存储（磁带）、链式存储 | 索引文件（NTFS）、散列文件 |

### 7.3 三种物理文件对比

| | 顺序文件 | 索引文件 | 散列文件 |
|------|----------|----------|----------|
| 存取速度 | 顺序时快 | **随机存取快** | 理想O(1) |
| 空间开销 | 无额外 | **需索引表（空间换时间）** | 无索引表（计算换空间） |
| 修改 | 需整体重写 | 仅修改索引 | 不便 |
| 缺点 | 仅顺序、碎片问题 | 索引表可能过大 | 冲突问题、仅定长记录 |
| 代表 | 磁带存储 | **Windows NTFS/FAT32** | 字典查询 |

> 🪟 **Windows磁盘文件物理结构 = 索引文件**

### 7.4 虚拟文件系统

将多个文件系统的**共同特性**进行抽象，形成与具体文件系统无关的虚拟层。

### 7.5 文件后缀

| 后缀 | 类型 |
|------|------|
| **BAT** | Windows命令文件（批处理） |
| EXE | 可执行文件 |
| COM | 二进制代码文件 |
| SYS | 系统文件 |

## 八、设备管理

### 8.1 缓冲技术

| 方面 | 内容 |
|------|------|
| **基本思想** | 主存开辟**缓冲区**，临时存放I/O数据，平滑CPU与设备速度差异 |
| **写操作** | 进程写缓冲区→继续计算；系统异步写入设备 |
| **读操作** | 系统先读设备数据到缓冲区；进程从缓冲区取数 |
| **作用** | ①协调速度差异 ②提高并行性 ③减少I/O等待 ④衍生虚拟设备(SPOOLing) |

### 8.2 驱动程序

| 方面 | 内容 |
|------|------|
| 定义 | 控制**计算机与外部设备**之间通信的特殊程序 |
| 本质 | 提供**硬件到操作系统**的接口 |
| 作用 | 硬件-系统接口、硬件控制、兼容性适配、功能优化、系统稳定 |
| 安装顺序 | **离核心越近越先装**（主板→显卡→声卡） |

### 8.3 临界资源

**一次只能被一个进程使用的资源**（需要互斥访问）

## 十、高频易错速查

| 陷阱 | 正确答案 |
|------|----------|
| 裸机=只装OS的计算机？ | ❌ =没装**任何软件**(含OS)的计算机 |
| Windows是多用户操作系统？ | ❌ =**单用户**多任务。UNIX才是多用户 |
| 批处理系统有交互性？ | ❌ 批处理=**脱机工作**，交互性是分时系统特征 |
| 批处理系统优点包括响应及时？ | ❌ 响应及时是**分时系统**的优点 |
| 早期批处理解决联机问题？ | ❌ 解决**脱机**问题 |
| 进程=作业？ | ❌ 进程是作业的**执行过程**，一个作业可对应多个进程 |
| 进程=程序？ | ❌ 程序**静态**永久，进程**动态**有生命周期 |
| I/O请求完成后进程进入执行态？ | ❌ 进入**就绪态**（阻塞→就绪） |
| 高级调度=进程调度？ | ❌ 高级=**作业调度**，低级=进程调度 |
| 死锁四个条件只要满足三个就可能死锁？ | ❌ 四个条件**缺一不可**，必须全部满足才死锁 |

| 按序号申请资源破坏的是不剥夺条件？ | ❌ 破坏**循环等待**条件 |
| 临界资源=正在被占用的资源？ | ❌ =**一次只能被一个进程使用**的资源 |
| Windows磁盘文件物理结构=顺序文件？ | ❌ =**索引文件**（NTFS/FAT32） |
| Windows命令文件后缀=EXE？ | ❌ 命令文件=**BAT**，EXE=可执行文件 |
| 存储器越高层CPU访问越间接？ | ❌ 越高层访问越**直接**、越快、越贵、越小 |
| 进程在不同系统中名称相同？ | ❌ 不同系统有不同名称（任务/活动等） |

| 4 | A | 高级调度=**作业调度**（后备→主存）。低级=进程调度（就绪→执行） |
| 5 | B | 一次性申请全部→不再"持有部分又请求其他"→破坏**请求与保持**条件 |
| 6 | B | I/O完成后进程从**阻塞→就绪**（等待条件满足，进入就绪队列） |
| 7 | C | 临界资源=一次只能被**一个进程使用**的资源。不是"正在占用"（那是忙资源） |
| 8 | D | 按序号申请→避免形成资源请求环→破坏**循环等待**条件 |
| 9 | D | 批处理优点：吞吐量大、利用率高、开销小。**响应及时是分时系统优点** |
| 10 | C | UNIX=**多用户多任务**。Windows才是单用户多任务 |
| 11 | D | 单CPU多道程序=**轮流运行**（时间片切换）。不能并行（单CPU） |
| 12 | C | Windows命令文件=**BAT**（批处理）。EXE=可执行，COM=二进制，SYS=系统 |
| 13 | A | 后备→执行=**作业调度**（高级调度）。就绪→执行=进程调度（低级） |
| 14 | C | M≥N×(W-1)+1 → 3≥2×2+1=5不满足 → **可能死锁** |
| 15 | C | Windows NTFS/FAT32=**索引文件**，支持随机存取 |

### 大题参考答案

**16. 操作系统定义与六大功能**

定义：管理计算机系统资源、控制程序执行、改善人机界面、提供各种服务的**系统软件**；用户与硬件之间的**接口**，计算机系统的**资源管理者**。

六大功能：①处理器管理 ②存储管理 ③文件管理（存储/检索/更新/共享/保护） ④设备管理 ⑤网络与通信管理 ⑥用户接口

**17. 进程 vs 程序 + 状态转换**

进程=程序关于某数据集合的一次**动态执行过程**，三要素=程序块+数据块+PCB。

| | 程序 | 进程 |
|------|------|------|
| 性质 | 静态 | 动态 |
| 存在 | 永久 | 有生命周期 |

状态转换图：
```
创建→就绪→执行→终止
       ↑    ↓
       ←阻塞←
```
- 就绪→执行：低级调度（进程调度）
- 执行→阻塞：I/O请求
- 阻塞→就绪：I/O完成
- 后备→执行：高级调度（作业调度）

**18. 死锁**

定义：多个进程间相互永久等待对方占用的资源，导致无法继续运行。

四必要条件（缺一不可）：
①互斥 ②请求与保持 ③不剥夺 ④循环等待

判断 M=4, N=3, W=2：M≥N×(W-1)+1 → 4≥3×1+1=4 **满足** → ✅ 不会死锁

预防：破坏任一条件即可。常见：一次性申请全部(破②)、按序号申请(破④)。

**19. 三大系统对比**

| | 批处理 | 分时 | 实时 |
|------|--------|------|------|
| 特征 | 成批处理、脱机 | 多用户联机、交互 | 及时响应 |
| 优点 | 吞吐量大、利用率高 | 响应及时、交互强 | 高可靠性 |
| 缺点 | 无交互、周转时间长 | 系统开销较大 | 功能较专一 |
| 适用 | 大型数据处理 | 多用户开发环境 | 工业控制、自动驾驶 |

**20. 三种文件物理结构**

| | 顺序文件 | 索引文件 | 散列文件 |
|------|----------|----------|----------|
| 优点 | 连续时速度快，组织简单 | 随机存取快，修改方便 | 无索引开销，理想O(1) |
| 缺点 | 仅顺序、碎片、修改需重写 | 需额外索引表 | 冲突、仅定长记录 |
| 适用 | 磁带存储、日志 | **通用磁盘(Windows)** | 关键字查询(字典) |

**Windows采用索引文件**：NTFS/FAT32通过索引表记录文件物理地址，支持随机存取和灵活修改，适合通用桌面/服务器场景。

## 一、数据结构基础

> 🍳 **费曼：数据像「食材」——生菜、肉、调料；数据结构像「摆盘方式」——火锅是一层层叠(线性)，圣诞树是分叉挂(树形)，朋友圈是互相@(图)。同样一堆食材，摆法不同，吃的效率完全不同。**

### 1.1 数据层级

| 层级 | 定义 | 例子 |
|------|------|------|
| **数据项** | **最小单位**，不可再分 | 一个字符、一个数字 |
| **数据元素** | 数据的基本单位 | 一条学生记录（学号+姓名+成绩） |
| **数据** | 计算机可识别、存储、加工的对象 | 所有数值和非数值信息 |
| **数据结构** | 数据元素间存在一种或多种关系的集合 | 线性表、树、图 |

### 1.2 四类基本数据结构

| 结构 | 关系 | 例子 |
|------|------|------|
| **集合** | 松散（元素同属一个集合） | {1, 2, 3} |
| **线性结构** | 一对一 | 线性表、栈、队列、串、数组 |
| **树形结构** | 一对多（层次） | 二叉树、文件目录 |
| **图形结构** | 多对多 | 社交网络、地图 |

### 1.3 线性 vs 非线性

| | 线性结构 | 非线性结构 |
|------|----------|------------|
| 关系 | **一对一** | 一对多（树）或多对多（图） |
| 前驱/后继 | 每元素最多一个前驱一个后继 | 至少一个元素≥2个前驱/后继 |
| 包含 | 线性表、串、栈、队列、数组 | **树、图、网** |

> ⚠️ **串是线性结构（特殊的线性表）！二叉树是非线性结构！线性链表也是线性结构（链式存储仍是线性逻辑）**

## 二、算法基础

> 🍳 **费曼：算法像「菜谱」——必须能做完(有穷性)，每一步写清楚不能含糊(确切性)，可以没有原料自带配方(0输入)，必须做出菜(至少1个输出)，每一步正常人都能做到(可行性)。**

### 2.1 五大特征

| 特征 | 说明 |
|------|------|
| **有穷性** | 有限步骤后必须终止（❌无穷性不是特征！） |
| **确切性** | 每步定义明确无歧义 |
| **输入** | 0个或多个 |
| **输出** | **至少1个**（无输出=无意义） |
| **可行性** | 每步可通过基本运算实现 |

### 2.2 三大控制结构

```
顺序结构 + 选择(分支)结构 + 循环结构
```
> ⚠️ 递归不是基本控制结构！嵌套也不是！

### 2.3 算法度量

| 度量 | 定义 | 符号 |
|------|------|------|
| **时间复杂度** | 执行所需**基本运算次数**（不是执行时间！） | O(n)、O(n²)、O(logn) |
| **空间复杂度** | 执行所需**存储空间**（不是程序长度！） | O(1)、O(n)、O(logn) |

> 🔑 **算法分析的目的：分析效率以求改进**

### 2.4 算法实现方式

子程序、函数、模块、过程 — 四种均可

## 三、线性结构

> 🍳 **费曼：顺序表像「电影院座位」——每人固定位置，找5号座直接走过去(随机存取)，但中间插一个人全场往后挪。链表像「寻宝游戏」——每人手里一张纸条写下一个人的位置，插入新人只需改两张纸条，但找第100个人要顺着99张纸条一路找。**

### 3.1 顺序表 vs 链表

| | 顺序表（数组） | 链表 |
|------|------|------|
| 存储方式 | 连续内存 | 不连续，通过指针链接 |
| 节点结构 | 只存数据 | **数据域 + 指针域** |
| 存取 | **随机存取**（下标直达） | 顺序存取（从头遍历） |
| 插入/删除 | 需移动大量元素 | **只需修改指针**（最大优势） |
| 物理vs逻辑 | **物理顺序=逻辑顺序** | 物理顺序≠逻辑顺序 |
| 存储空间 | 只存数据 | 需额外存储指针 |
| 搜索 | 更简单（可折半查找） | 只能顺序查找 |
| 排序 | 更简单（下标交换） | 需修改指针，复杂 |

### 3.2 顺序表插入/删除（等概率）

```
n个元素：
插入平均移动 = n/2
删除平均移动 = (n-1)/2

例：127个元素，插入平均移动 = 127/2 = 63.5
                删除平均移动 = 126/2 = 63
```

### 3.3 栈 vs 队列

| | 栈 | 队列 |
|------|------|------|
| 原则 | LIFO（后进先出） | FIFO（先进先出） |
| 操作端 | 仅栈顶 | 队头删除、队尾插入 |
| **共同点** | **都只允许在端点处插入和删除** | ← 这是考点！ |

### 3.4 数组存储方式

| 方式 | 顺序 |
|------|------|
| **行序优先** | 先一行行→一行完再下一行 |
| 列序优先 | 先一列列→一列完再下一列 |

## 四、非线性结构

> 🍳 **费曼：树像「公司组织架构」——CEO(根)管几个VP，每个VP再管几个经理(一对多)，不能出现"经理同时向两个VP汇报"(无环)。图像「朋友圈」——A认识B、B认识C、C也认识A，可以互相@，可以有环。**

### 4.1 树的基本概念

| 概念 | 定义 |
|------|------|
| **树的度** | 树内**节点度的最大值**（下级节点最多的那个节点的下级个数） |
| 节点度 | 该节点的子树个数 |
| 叶子节点 | 度为0的节点 |
| 二叉树 | 每个节点**最多2个子树**，**有序**（左右子树不能互换） |

### 4.2 树 vs 二叉树 vs 图

| | 树 | 二叉树 | 图 |
|------|------|------|------|
| 节点度 | 无限制（可>2） | **最大为2** | 无限制 |
| 有序性 | 无序（子树无左右） | **有序**（左右不可互换） | — |
| 双亲 | 除根外**唯一** | 除根外唯一 | 可有**多个** |
| 环 | **无环** | 无环 | 允许环 |
| 模型 | **层次模型** | — | 网状模型 |

> 🌲 **树 = 连通无环图**（特殊的图）

### 4.3 完全二叉树叶子节点公式

```
n为奇数 → 叶子数 = (n+1)/2
例：699个节点(奇数) → 叶子 = (699+1)/2 = 350
```

### 4.4 二叉树遍历（线性化操作）

| 方式 | 顺序 |
|------|------|
| **先序** | 根 → 左子树 → 右子树 |
| **中序** | 左子树 → 根 → 右子树 |
| **后序** | 左子树 → 右子树 → 根 |

遍历的应用：文件系统遍历(先序)、XML/HTML解析、数据库B+树索引、地图路径查找

## 五、查找算法

> 🍳 **费曼：顺序查找像「翻字典逐页找」——从第一页翻到最后一页，找到就停。折半查找像「猜数字游戏」——每次都猜中间，比大小后砍掉一半，log₂n次必中。前提是字典已经排好序。**

### 5.1 顺序查找（有序表 vs 无序表）

| 情况 | 平均查找长度 | 有序 vs 无序 |
|------|-------------|-------------|
| 查找失败 | n+1 | **相同**（都需遍历全部） |
| 查找成功（唯一k） | (n+1)/2 | **相同**（都从表头遍历，找到停止） |
| 查找成功（多个k，全找出） | n | **相同**（都需完整遍历） |

> 🔑 **顺序查找时，有序表和无序表查找长度完全相同！有序性在顺序查找中没有优势。**

### 5.2 折半查找 vs 二叉排序树

| | 折半查找 | 二叉排序树(BST) |
|------|----------|------|
| 前提 | 有序顺序表 | 构建BST |
| 平均 | O(logn) | O(logn)（平衡时） |
| 最坏 | O(logn) ✅ | O(n) ❌（退化成链表） |
| 结论 | **折半查找更优**（性能稳定） | 取决于平衡性 |

## 六、排序算法

> 🍳 **费曼：冒泡像「水中气泡」——最大的泡泡自己浮到水面。选择像「挑苹果」——每次从筐里挑最小的放篮子里。快速排序像「分班」——选一个标准分(枢轴)，矮的站左边高的站右边，左右再各自分班。**

### 6.1 四大排序对比

| | 冒泡排序 | 选择排序 | 插入排序 | 快速排序 |
|------|----------|----------|----------|----------|
| 思想 | 相邻比较交换，大者**冒泡**到末尾 | 每次选最小放入结果 | 将元素插入已排序部分 | 选枢轴**分治**，递归排序 |
| 最好 | O(n) | O(n²) | O(n) | O(nlogn) |
| 平均 | O(n²) | **O(n²)** | O(n²) | **O(nlogn)** |
| 最坏 | O(n²) | **O(n²)** | O(n²) | O(n²) |
| 空间 | O(1) | O(1) | O(1) | O(logn)~O(n) |
| 稳定 | ✅ 稳定 | ❌ 不稳定 | ✅ 稳定 | ❌ 不稳定 |

> 🔑 **选择排序：最佳=最坏=O(n²)** —— 无论顺序如何，每次都要遍历剩余全部元素找最小

### 6.2 冒泡排序关键特征

- 通过比较**相邻元素**，逆序则交换
- 每次遍历后最大元素"冒泡"到末尾
- ❌ 不选择最小元素放正确位置（那是选择排序）
- ❌ 不用分治策略（那是快速/归并排序）
- ❌ 时间复杂度不是O(nlogn)（是O(n²)）

## 七、递归

> 🍳 **费曼：递归像「俄罗斯套娃」——打开一个娃，里面还有个小一号的娃，一直开到最小的那个(边界条件)，然后一层层合回去(回归)。**

### 7.1 递归三要素

| 要素 | 说明 |
|------|------|
| **边界条件** | 最小规模可直接求解（递归出口） |
| **递归关系** | 大问题分解为同类小问题 |
| 执行过程 | **递推**（大→小，直到边界） → **回归**（小→大，逐层返回） |

### 7.2 递归适用场景

- ✅ 数据定义是递归的（如斐波那契数列）
- ✅ 问题解法是递归的（如梵天塔）
- ✅ 数据结构是递归的（如二叉树遍历）

### 7.3 递归优缺点

| 优点 | 缺点 |
|------|------|
| 代码简洁易懂 | **效率低**（保存栈帧开销+可能重复计算） |
| 符合人类思维（分治直观） | **栈溢出风险**（深度过大→崩溃） |
| 便于维护 | 调试困难（调用链长难跟踪） |

## 八、综合应用题模板

### 8.1 字符频度统计

```python
def count_freq(s):
    freq = {}
    for char in s:
        freq[char] = freq.get(char, 0) + 1
    return freq
```

### 8.2 输油管道最优位置（中位数问题）

- 水平主管道 → 只关心y坐标
- 目标：min Σ|yᵢ - k|
- **最优k = y坐标的中位数**
- 奇数个 → 中位数；偶数个 → 中间两个任意值均可

### 8.3 顺序表平均移动

```
n元素顺序表，等概率：
插入 n/2 个元素移动
删除 (n-1)/2 个元素移动
```

## 九、高频易错速查

| 陷阱 | 正确答案 |
|------|----------|
| 算法五大特征包含"无穷性"？ | ❌ 包含**有穷性**（有限步终止），不是无穷性 |
| 递归是算法的基本控制结构？ | ❌ 基本结构=**顺序+选择(分支)+循环**，递归不是 |
| 算法时间复杂度=执行时间？ | ❌ =执行所需**基本运算次数** |
| 算法空间复杂度=程序长度？ | ❌ =执行所需**存储空间** |
| 数据处理最小单位=数据元素？ | ❌ 最小单位=**数据项**（不可再分），数据元素是基本单位 |
| 二叉排序树查找一定O(logn)？ | ❌ 最坏退化成链表=**O(n)**，折半查找始终O(logn)更优 |
| 有序表顺序查找比无序表快？ | ❌ 顺序查找时**完全相同**（都从表头遍历） |
| 二叉树是线性结构？ | ❌ 二叉树=**非线性**结构 |
| 线性链表是非线性结构？ | ❌ 逻辑上仍是**线性**结构（链式只是存储方式） |
| 栈和队列没有共同点？ | ❌ 共同点：**只允许在端点处插入和删除** |
| 冒泡排序时间复杂度O(nlogn)？ | ❌ 平均/最坏=**O(n²)** |
| 选择排序最佳情况比最坏好？ | ❌ 选择排序最佳=最坏=**O(n²)**，与初始顺序无关 |
| 链表优点是随机存取？ | ❌ 链表只能顺序存取，优点是**插入删除方便（改指针）** |
| 串是非线性结构？ | ❌ 串=特殊的线性表=**线性**结构 |
| 存储结构=数据在计算机中的顺序存储方式？ | ❌ =**逻辑结构在计算机中的表示（映像）** |
| 树的度=节点的子树个数？ | ❌ 节点的子树个数=**节点度**，树的度=**所有节点度的最大值** |

## 十一、答案与解析

### 选择题答案

| 题号 | 答案 | 解析 |
|------|------|------|
| 1 | C | **数据项**是数据处理最小单位（不可再分）。数据元素是基本单位，数据是总称 |
| 2 | C | 时间复杂度=**基本运算次数**（不是实际时间）。A是绝对时间，B是程序长度，D是指令条数 |
| 3 | D | 三大基本结构：**顺序+选择(分支)+循环**。递归是算法设计方法，不是控制结构 |
| 4 | C | **二叉树**=非线性结构。队列、线性表、栈都是线性结构（一对一关系） |
| 5 | B | 顺序查找：有序vs无序**完全相同**（都从表头遍历，查找失败都需n+1次比较）。A错，C错（无序也可），D错（O(n)） |
| 6 | C | 链表最大优势：插入删除**只需改指针**，不移动元素。A错（不能随机存取），B错（多存指针），D错（物理顺序≠逻辑顺序） |
| 7 | C | 栈和队列共同点：**都只在端点操作**（栈=栈顶，队列=两端）。A是栈独有，B是队列独有 |
| 8 | B | 折半查找最坏保持O(logn)，BST最坏退化O(n)→**折半更优** |
| 9 | B | 冒泡=相邻比较交换，大元素冒泡。A是选择排序，C是快速/归并，D错(O(n²)) |

### 大题参考答案

**16. 算法五大特征与复杂度**

| 特征 | 说明 |
|------|------|
| 有穷性 | 有限步后必须终止 |
| 确切性 | 每步无歧义 |
| 输入 | 0个或多个 |
| 输出 | 至少1个 |
| 可行性 | 每步可通过基本运算实现 |

- **时间复杂度**：执行所需基本运算次数，衡量算法运行效率（不是实际秒数）
- **空间复杂度**：执行所需存储空间，衡量算法内存消耗（不是程序长度）

**17. 顺序表 vs 链表**

| | 顺序表 | 链表 |
|------|------|------|
| 优点 | 随机存取(O(1))、排序简单 | **插入删除方便**（改指针，不移动元素） |
| 缺点 | 插入删除需大量移动元素 | 只能顺序存取、多存指针 |

127个元素，等概率：
- 插入平均移动 = 127/2 = **63.5**个
- 删除平均移动 = 126/2 = **63**个

**18. 三大排序对比**

| | 冒泡 | 选择 | 快速 |
|------|------|------|------|
| 思想 | 相邻比较交换，大者冒泡 | 每轮选最小放前面 | 选枢轴分治，递归 |
| 最佳 | O(n) | **O(n²)** | O(nlogn) |
| 最坏 | O(n²) | **O(n²)** | O(n²) |
| 稳定性 | ✅ | ❌ | ❌ |

选择排序最佳=最坏=O(n²)：因为每轮都必须遍历剩余全部元素找最小，比较次数恒为n(n-1)/2，与输入顺序无关。

**19. 递归**

定义：算法在执行过程中直接或间接调用自身。核心：将大问题分解为同类小问题。

两个条件：
- **边界条件（递归出口）**：最小规模可直接求解
- **递归关系**：大问题→小问题的分解规则

优缺点：
- ✅ 代码简洁、符合思维、便于维护
- ❌ 效率低(栈帧+重复计算)、栈溢出风险、调试困难

**20. 树 vs 二叉树 vs 图**

| | 树 | 二叉树 | 图 |
|------|------|------|------|
| 节点度 | ≤n | **≤2** | ≤n |
| 有序性 | 无序 | **有序**（左右不可换） | — |
| 双亲 | 唯一 | 唯一 | 可多个 |
| 环 | 无 | 无 | 允许 |

完全二叉树：除最后一层外每层全满，最后一层节点靠左排列。

699节点(奇数) → 叶子数 = (n+1)/2 = 700/2 = **350**
